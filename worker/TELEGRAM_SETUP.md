# Telegram-first канал питания: отдельный бот без веб-приложения

## Что уже в коде

Создан самостоятельный безопасный Cloudflare Worker `worker/telegram-bridge.mjs`. Он принимает фото **или** текст через личный чат Telegram-бота, запрашивает **один** анализ OpenAI для нового приёма еды, предлагает текст и КБЖУ для проверки, затем **только по явному подтверждению** публикует в канал одним постом с прогресс-барами.

- Канал может содержать текст с emoji-барами; отдельный Mini App/WebView не нужен.
- Когда исходник — Telegram-фото, бот публикует то же фото. Фото не сохраняется на сервере, используется Telegram `file_id`.
- В сообщении: еда, калории/белок, дневной итог, 10-сегментные полосы и остатки.
- Настройки через личный чат: `/goal 2350 175`, `/weight 84.8`, `/today`.
- Если AI оценил неверно: `✏️ Исправить КБЖУ` → `/edit 300 35`, затем публикацию надо подтвердить ещё раз.
- **Отправка каждого отдельного подхода/замера веса не вызывает OpenAI.** Вес хранится в KV и не меняет цели автоматически.
- Текущие базовые цели **2350 ккал и 175 г белка**. Начальный вес для нового пользователя **84,8 кг**, но его стоит подтвердить `/weight 84.8`.
- Без открытого Telegram-бота или подключённого инструмента публикации скриншоты **из чата ChatGPT** сами не попадут в Telegram. Этот режим предполагает, что фото присылают напрямую личному Telegram-боту. Для отправки непосредственно из ChatGPT можно отдельно подключить сервис публикации.
- В текущей версии обрабатывается одно входящее фото или одно описание на черновик. Альбом из нескольких фото пока **не объединяется** в один анализ. Не отправляйте серию упаковок как один приём и не рассчитывайте, что бот их склеит.
- Данные питания, отправленные Telegram-боту, хранятся как суммы дня и черновики в KV. Не содержит общей синхронизации с браузерными записями «Рацион+» (это отдельный режим, иначе возник бы двойной учёт).
- Модель по умолчанию `gpt-6-luna`, её можно заменить секретом/переменной `OPENAI_MODEL`. **Нужен отдельный оплачиваемый OpenAI API; ChatGPT Plus не покрывает его расходы**.
- Возможны неточности при распознавании упаковок и массы порции: перед отправкой есть предпросмотр и редактирование. Это не медицинское приложение и не измеритель калорий с гарантированной точностью.

## Настройка сервера

1. Создай в Telegram бота через официального **@BotFather**, открой ему личный чат; добавь бота администратором в свой канал с правом публиковать сообщения.
2. Создай Cloudflare Workers + KV (или используй уже созданное KV из основного Worker). Создай конфиг по шаблону `worker/wrangler.telegram.toml.example`; заполни только ID KV-пространства. Не помещай секреты в этот файл.
3. В Cloudflare Workers создай секреты `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` (например, `@mychannel`), `TELEGRAM_OWNER_ID` (твой числовой id Telegram), `TELEGRAM_WEBHOOK_SECRET` (случайная строка A–Z, a–z, 0–9, дефис и подчёркивание), `OPENAI_API_KEY`. Не присылай токены в переписку и не загружай их в GitHub. **Секреты нужны на сервере, а не в браузере и не в исходниках.**
4. `cd worker` → `npx wrangler deploy -c wrangler.telegram.toml` (перед этим создай файл `wrangler.telegram.toml` по примеру).
5. После получения HTTPS-адреса Worker установи webhook из защищённого терминала:
```sh
curl -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  --data-urlencode "url=https://YOUR-WORKER.workers.dev/telegram-webhook" \
  --data-urlencode "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
  --data-urlencode 'allowed_updates=["message","callback_query"]'
```
   Команда предполагает, что переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` уже заданы у тебя локально в защищённом терминале. Не вставляй реальные значения в публичный скриншот.
6. Протестируй сначала на **закрытом тестовом канале**: `/start` → фото → предпросмотр → `/edit` при необходимости → `✅ Опубликовать` → `/today`. Потом меняй `TELEGRAM_CHANNEL_ID` на основной канал.

## Защита и ограничения

- Вход только по HTTPS и секрету заголовка Telegram `X-Telegram-Bot-Api-Secret-Token`.
- Все запросы, не принадлежащие числовому `TELEGRAM_OWNER_ID` и не пришедшие из приватного чата, игнорируются.
- Кнопки подтверждения проверяют владельца черновика; URL и данные HTML экранируются.
- Защита от повторов: уникальные Telegram `update_id` и статус `published` сохраняются в KV.
- **Ограничение:** KV не предоставляет атомарных блокировок. При редкой одновременной доставке двух одинаковых callback возможны повторы, поэтому нельзя считать это банковской защитой от дублей. Для гарантированной семантики *ровно один раз* нужен Durable Object/реляционная транзакция + очередь/аутбокс.
- Если Telegram принял пост, а запись прогресса в KV не удалась, пост мог появиться без суммирования; бот попросит проверить канал. Это существенная причина протестировать обработку повторов до реального использования.
- Входящая фотография передаётся в OpenAI API при запросе, что важно для приватности.
- Используй раздельные тестовые и боевые токены/каналы.

## Тесты

Тест на GitHub Actions: `node tests/test_telegram_bridge.mjs`. Проверяет запрет неавторизованного webhook, игнорирование чужих аккаунтов, настройку целей и веса, один запрос AI на фото, предпросмотр, публикацию после нажатия и отсутствие простого дублирования. Это **не** заменяет тест на живом Telegram, iPhone, Cloudflare KV и реальные лимиты API.

## Напоминание про вес

84,8 кг — отдельный утренний замер. Не стоит менять калораж 2350 по одной цифре. 175 г белка — примерно 2,06 г/кг, что близко к прежней выбранной стратегии. Лучше смотреть на средний вес 7 утренних измерений и сравнивать недельные средние.

# Telegram-канал и учёт питания — настройка

В проекте есть **два разных варианта**, не путать их.

## A. Самый простой: из ChatGPT через Upload-Post

Связать свой Telegram-канал с Upload-Post. После этого ChatGPT может подготовить текст, КБЖУ и эмодзи-прогресс-бары в этой беседе и отправить **текстовый** пост через подключённую платформу **после согласования**. Фото, приложенное к ChatGPT, напрямую в Upload-Post не передаётся: для него нужно отдельно выбрать файл через Upload Studio. Этот путь не требует собственного OpenAI API, но зависит от тарифа и лимитов Upload-Post.

## B. Независимый приём пищи прямо в Telegram-боте

Приватный бот получает текст и фото → складывает их как черновик → **только после команды /рассчитать** запускает одну платную AI-оценку → показывает текст с калориями, белком и текстовыми прогресс-барами → даёт выбор фото или публикации без него → **только после нажатия «Опубликовать в канал»** отправляет запись в канал и обновляет дневные суммы. Не публикует автоматически без подтверждения. Голосовые сообщения пока не обрабатываются.

Здесь используется код `worker/index.js` + `worker/telegram-bot.mjs` и Cloudflare Workers KV. Репозиторий GitHub публичный — **никакие секреты, личные токены и данные владельца сюда не вносят**.

### Что нужно подключить

1. Создать бота через официальный @BotFather в Telegram; сохранить его API-токен **в защищённом месте**, НЕ в GitHub и НЕ в чате.
2. Добавить бота администратором своего Telegram-канала с правом публиковать сообщения. Подключить ID канала через защищённый секрет `TELEGRAM_CHAT_ID` (публичный @channelusername либо числовой ID приватного канала).
3. Узнать свой числовой Telegram user ID и установить `TELEGRAM_OWNER_IDS` — один ID или несколько через запятую. Для безопасности бот отвечает **только этим ID и только в личном чате**.
4. Развернуть Cloudflare Worker в своей учётной записи (см. `README.md`). Создать и привязать KV namespace `PROGRESS`, выставить `ALLOWED_ORIGIN` для GitHub Pages и модель `OPENAI_MODEL = "gpt-5-mini"`.
5. В **Cloudflare → Worker → Settings → Variables and Secrets** добавить secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_OWNER_IDS`, `TELEGRAM_WEBHOOK_SECRET`, `OPENAI_API_KEY`. Последний оплачивается отдельно от ChatGPT Plus. Вебхук принимает запросы исключительно с корректным секретом Telegram.
6. В Telegram Bot API вызвать `setWebhook` с URL `https://ВАШ-АДРЕС.workers.dev/telegram/webhook` и параметром `secret_token` (то же значение, что и `TELEGRAM_WEBHOOK_SECRET`). Не публикуйте этот вызов со включённым токеном бота; делайте его из защищённой среды/скрипта. Можно проверить состояние через `getWebhookInfo`.
7. Сначала проверить публикацию в **тестовый канал**: отправить боту фото и текст, написать `/рассчитать`, исправить КБЖУ при необходимости и подтвердить публикацию. Только после этого сменить `TELEGRAM_CHAT_ID` на рабочий канал.

**Команды:** `/start` — справка; `/рассчитать` — один платный анализ накопленных фото/текста; `/поправить 500 40 15 50` — поправить вручную ккал, белки, жиры, углеводы **без ИИ**; `/итог` — дневной прогресс без ИИ; `/вес 84.8` — утреннее взвешивание без ИИ; `/цель 2350 175` — дневные цели; `/сброс` — очистить черновик.

**Важно:** подсчёты из старых переписок ChatGPT и из локального браузера «Рацион+» **не синхронизируются автоматически** с ботом. Для первых сообщений дневной прогресс начнётся с нуля, если не занести исходные суммы. Чат-бот ничего не знает о фото, отправленных в ChatGPT; отправлять нужно в Telegram-бот или использовать вариант A.

**Проверки:** GitHub Actions запускает `node tests/test_telegram.mjs` (проверки доступа посторонних, тайного ключа вебхука, одного AI-запроса после команды, ручной коррекции, подтверждения публикации, защиты от повторных callback и дневного счётчика). Это тесты с имитацией внешних сервисов — не живой тест Telegram и OpenAI.

**Ограничения:** до 12 фотографий для одного приёма; изображения со сжатием Telegram; внешние фото и состав следует проверять, а расчёт по фото — оценочный. Защита от одновременных дублей на KV не атомарна; при сетевой ошибке проверьте канал перед повторной публикацией. Текстовые «полоски» внутри поста — эмодзи: полноценный интерактивный Telegram-виджет невозможно встроить прямо в произвольное сообщение без мини-приложения.

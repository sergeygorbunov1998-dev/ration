# Рацион+ — питание, тренировки и прогресс

**Статус:** рабочий локальный прототип PWA; сервер для AI/Telegram и виджета требует отдельного развёртывания и секретов. **Никаких секретов в публичном GitHub.**

## Обновления 19.11.2026

- Экран тренировок: контекстный итог последней тренировки вместо постоянного предупреждения; рекомендации по технике по кнопке ⓘ (пока текстовые, без иллюстраций).
- Тренировка в процессе: уже предложенные веса и подходы, отметки **каждого сделанного подхода**, фактические повторения, дискомфорт, комментарии, сохранение черновика и продолжение без сети. Незаполненные подходы **не считаются выполненными**.
- По завершении тренировки: ровно один запрос ИИ-анализа, **только если** настроен сервер; никакого ИИ при отметке каждого подхода. Оценка предполагает, что данные питания могли быть неполными.
- Программа тренировок: ИИ может предложить изменение с учётом истории тренировок, текущего рациона, веса и этапа возвращения; план применяется **только после редактирования/подтверждения** пользователем.
- Импорт из заметок iPhone: поддерживает как строки «Название — 50 кг — 2×12», так и журнал «Название [таб] 2/12 (все сделал) [таб] 50» с записью выполненных/пропущенных упражнений в историю.
- Повторные приёмы пищи сохраняются в локальную базу и при том же составе/граммовках подставляются **без расхода API**. После ответа ИИ база дополнительно пополняется карточками отдельных продуктов с весами (если распознаны). Непроверенный продукт с новой граммовкой требует подтверждения.
- Для незнакомого продукта можно отдельно разрешить веб-поиск по сайту производителя (дополнительный платный вызов). Источники отображаются ссылками, если модель их вернула.
- Замеры веса считают недельный тренд локально, без ИИ. В профиле есть ориентировочный счётчик расходов на API по токенам, которые сообщил сервер.
- Apple Health/HealthKit **не подключён**: шаги пока вводятся вручную. Нативный виджет iOS также потребует отдельной разработки.
- До развёртывания Cloudflare Worker и подключения API анализ еды, программ тренировок и Telegram **не будут работать**. Интерфейс и ручные записи доступны.

## Доступно без сервера

- Мобильная домашняя панель с кольцом калорий и полосками белка, жиров, углеводов.
- Несколько раздельных профилей, редактируемые цели, рост, вес, возраст, активность, режим (снижение/поддержание/набор).
- Примерный расчёт целей по Mifflin–St Jeor + выбранному коэффициенту активности; ручная корректировка.
- Приёмы пищи: ручной ввод, до 30 фотографий блюда/упаковки/этикетки (добавление несколькими порциями, удаление отдельных снимков, выбор фотографии для Telegram или публикация без неё), дневная и общая история, исправление/удаление.
- Фотографии сжимаются до 1200px и хранятся локально в IndexedDB, текстовые записи — в localStorage.
- Тренировки Full Body: программа, веса, повторы, подходы, отметки боли, ощущений, история, редактирование.
- Измерения веса/талии, график веса, экспорт/импорт резервной копии **включая фотографии**.
- PWA (офлайн-кэш, иконка на экране «Домой»).

## Подключения (после развёртывания Worker)

- Фото и текст → OpenAI Responses API → оценка калорий и БЖУ с обязательным подтверждением пользователем.
- Сохранённое и подтверждённое блюдо → Telegram Bot API → публикация сообщения с выбранным фото либо без фото в канал после предпросмотра, редактирования подписи и явного нажатия «Отправить». Публикация без отдельного согласия не выполняется.
- Отправка сумм дня в Workers KV → Scriptable виджет iOS через только-чтение ключ.
- Чат ChatGPT **не синхронизируется с приложением автоматически**. Веб-приложение использует отдельный OpenAI API, а не историю бесед и не подписку ChatGPT.

## Публикация статического интерфейса на GitHub Pages

**Важно:** стандартное подключение GitHub в ChatGPT предназначено для чтения репозиториев, а не для записи. Ошибку 403 при попытке загрузки исходников невозможно исправить простым выбором репозитория. Публикация требует Codex с доступом на запись или загрузки файлов через GitHub UI.

Содержимое **корня этой папки** (`index.html`, `app.js`, `style.css`, `manifest.webmanifest`, `sw.js`, картинки) положить в корень репозитория. `worker` и `widget` могут остаться рядом как исходники. В GitHub: Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/ (root)` → Save. По умолчанию сайт: `https://USERNAME.github.io/ration/`.

## Настройка защищённого сервера (Cloudflare Workers)

Понадобятся аккаунт Cloudflare, отдельный OpenAI API key с включённой оплатой по использованию (подписка ChatGPT не является API-платежом), а для публикаций — свой Telegram Bot, добавленный администратором в нужный канал.

1. В папке `worker/` скопировать `wrangler.toml.example` в `wrangler.toml`, указать свой GitHub Pages origin и имя Worker.
2. Установить Node.js; войти в Cloudflare через `npx wrangler login`.
3. Создать KV: `npx wrangler kv namespace create PROGRESS`, затем добавить полученный `id` в `wrangler.toml` по примеру.
4. Ввести секреты через `npx wrangler secret put APP_ACCESS_KEY`, аналогично `OPENAI_API_KEY`, `WIDGET_READ_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (для последнего допустим `@channelusername` или числовой id канала). **Никогда не класть их в GitHub, браузерный HTML или код виджета, кроме отдельного READ_KEY виджета.**
5. Развернуть: `npx wrangler deploy`.
6. В приложении: Профиль → Настроить сервер → HTTPS URL `https://….workers.dev` и **APP_ACCESS_KEY** (код доступа). Проверь соединение.
7. Для Telegram включи предложение предпросмотра **после сохранения**. Приложение никогда не отправляет пост само: отправку подтверждают отдельной кнопкой; можно редактировать подпись и выбирать фото или вариант без фото. У бота должны быть права публикации в указанном канале.

`APP_ACCESS_KEY` — длинный случайный секрет, который используется только на личных устройствах. Не публикуйте его. Для публичного приложения с большим количеством пользователей нужна полноценная авторизация, ограничения частоты и серверная БД, а не общий ключ.

### Виджет на экран блокировки

Скачать Scriptable на iPhone, создать скрипт из `widget/RationWidget.js`, поставить SERVER, WIDGET_READ_KEY, PROFILE_ID (ID профиля указан в настройках приложения). Добавить виджет Scriptable на экран блокировки и выбрать созданный скрипт. На домашний экран также можно добавить виджет Scriptable. iOS определяет частоту обновления виджетов — она не мгновенная. Браузерная PWA **сама не создаёт системные виджеты iOS**.

## Изменения для iPhone

- Более компактный главный экран с учётом безопасной зоны статус-бара.
- Встроен импорт программы тренировок из текстовых заметок (`.txt` или копирование текста), с предпросмотром и подтверждением до замены плана. Историю тренировок при этом приложение не изменяет.
- Для новых записей питания ручная правка БЖУ скрыта за раскрывающимся блоком. Автоматический расчёт начнёт работать только после подключения сервера.
- GitHub Actions автоматически публикует сайт и запускает базовые проверки синтаксиса и сервера.

## Архитектура и ограничения

GitHub Pages отдаёт интерфейс; он не выполняет безопасную серверную интеграцию. Cloudflare Worker хранит секреты в своих настройках, вызывает OpenAI и Telegram, сохраняет **только дневные суммы для виджетов** в KV. Полные записи, фото, упражнения и личные параметры остаются в браузере и не синхронизируются между устройствами: сделай резервную копию при переносе. OpenAI и Telegram получат фото только при соответствующих вызовах, это стоит учитывать для приватности.

Сервис Worker защищён общим ключом (семейный прототип, не сервис для массовой аудитории). Защита от дублей Telegram через KV допускает редкие гонки; при ошибках сети можно ошибочно повторить отправку — перед повтором проверь канал. До публикации в реальном канале стоит проверить его на тестовом канале.

## Проверки

`node --check app.js` и `node --check worker/index.js` для синтаксиса. UI можно локально открыть через `python -m http.server 8000` из корня.
